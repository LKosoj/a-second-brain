# Предложение по меню d-brain

Статус: структура согласована пользователем 09.10.2026 и реализована локально. Без коммита, перезапуска и развёртывания.

## Что подтверждено

- `bot/dashboard.py:186` показывает 11 действий; закрытие находится посередине.
- `bot/dashboard.py:533` уже редактирует одно сообщение, но через MarkdownV2.
- EzoBot в `utils/rich_delivery.py:232` встраивает кнопки в Rich Message через
  `tg-button-row` и `tg-button`, сохраняя данные нажатий.
- Установлен aiogram 3.31.0: поддерживает InputRichMessage и редактирование rich_message.
- `bot/replies.py` уже содержит отправку и редактирование Rich Messages.
- В `handlers/menu.py` переход домой и закрытие не прекращают ожидание ввода
  запроса/брифа. Поэтому следующее сообщение может попасть в прежний сценарий.
- Статистики частоты использования и проверки на телефоне нет; приоритеты ниже
  являются предложением, а не измеренным предпочтением пользователя.

## Варианты

1. Рекомендуемый: запрос прямо на главном экране; остальные действия по смыслу
   в разделах. Меньше выбора на первом экране, дополнительное нажатие для отчётов.
2. Все действия на главном экране с понятными подписями и новым порядком.
   Минимальная правка, но остаётся 11 равнозначных действий.
3. Все действия внутри разделов. Самый короткий главный экран, но дополнительное
   нажатие даже для запроса. Для личного помощника это неудобно.

## Предлагаемый главный экран

Текст: «d-brain. Сохраняй мысли голосом или текстом — просто отправь сообщение.
Сегодня: N записей. Выбери, что сделать».

```text
[ ✨ Задать вопрос или поручение              ]
[ 📋 Сводки              ][ 🗂 Требуют решения ]
[ 📁 Мои файлы           ][ ⚙️ Разобрать записи ]
[ ⋯ Ещё                                     ]
[ Закрыть меню                              ]
```

Сводки: «Сводка дня», «Обзор недели», «Собрать справку» (нынешний бриф).
Разобрать записи: «Показать разбор» и «Обработать и сохранить».
Перед выбором явно объясняется: первое действие не сохраняет изменения;
второе может создать задачи и обновить заметки.
Ещё: статистика, «Автообработка» (отключённые шаги), справка.

## Карта переходов

| Экран | Действия | Возврат |
|---|---|---|
| Главный | Запрос, сводки, решения, файлы, разбор, ещё | Закрыть |
| Сводки | День, неделя, собрать справку | Главное меню |
| Тип справки | Решение, тема, проект → ввод названия | К сводкам |
| Разбор записей | Показать разбор, обработать и сохранить | Главное меню |
| Ещё | Статистика, автообработка, справка | Главное меню |
| Требуют решения | Список → пункт → существующие действия | Главное меню |
| Пункт решения | Существующие действия | К списку с прежней страницей |
| Файлы | Раздел → папка → выдача файла | К разделам / вверх |
| Статистика / автообработка | Обновление / существующее включение шага | К «Ещё» |
| Обзор недели | Просмотр, существующее подтверждение, решения | К сводкам |
| Ввод запроса / справки | Текст или поддерживаемое голосовое, отмена | Родительский экран |

На вложенных экранах единый нижний ряд: «Назад», «Главное меню», «Закрыть».
У страниц понятные подписи «Предыдущие» / «Следующие».
Выход из ввода прекращает ожидание следующего сообщения.

## Согласованная реализация

1. Изменить тексты и группировку в существующих построителях меню.
2. В существующем render_dashboard формировать Rich Message со встроенными
   кнопками и обновлять тот же message_id. Использовать установленный aiogram;
   отдельный клиент, база или настройка режима не нужны.
3. Сохранить все существующие menu:* данные нажатий. Новые данные нужны только
   новым экранам разделов и отмене ввода. Старые кнопки продолжают работать.
4. Меню служит навигацией. Ответы, сводки и скачанные файлы остаются отдельными
   сообщениями, к которым можно вернуться. Ввод начинается на обновлённом экране.
5. Подтверждать нажатие до чтения файлов или запуска работы. Для долгой работы
   использовать существующие сообщения о ходе выполнения.
6. Сохранить существующий обычный путь доставки при отказе Rich Messages,
   передавая ему обычную клавиатуру. Без нового переключателя режима.

## Проверка

- Карта доступности: все прежние 11 действий достижимы.
- Первый экран отправляется как Rich Message; переход редактирует его ID;
  встроенные кнопки содержат прежние данные нажатий.
- Старые сообщения, повторное нажатие и удалённое меню обрабатываются корректно.
- При отказе rich-доставки обычное меню сохраняет рабочие кнопки.
- «Назад», «Главное меню», «Закрыть» во время ввода снимают ожидание запроса;
  следующее сообщение сохраняется обычным способом.
- Проверки затрагивают меню и связанный ввод; используются временные хранилища.
- Живая проверка в Telegram после отдельного разрешения на запуск: узкий экран,
  длинные подписи, встроенные кнопки, возвраты, выдача файла, ввод и отмена.

## Результат реализации

- Rich Message использует безопасный HTML из существующего преобразователя
  Markdown и встроенные `tg-button-row` / `tg-button`, как в EzoBot.
- Первые семь кнопок соответствуют согласованному главному экрану. Все прежние
  11 действий доступны через разделы; прежние данные нажатий сохранены.
- Ввод запроса и справки открывается в сообщении меню. Навигация, закрытие,
  `/menu` и `/files` прекращают ожидаемый ввод. После отправки запроса или `-`
  экран возвращается к главному меню либо к сводкам.
- Нажатия навигации подтверждаются перед построением экрана; отправка файла
  показывает «Отправляю файл…» перед чтением и отправкой.
- Rich-доставка и обычная доставка используют один существующий механизм
  отрисовки; отдельного клиента, настроек режима и хранилища не добавлено.
- Использованы brainstorming, telegram-bot-ui и 97-dev.
