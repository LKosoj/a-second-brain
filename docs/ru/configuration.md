# Конфигурация

[English](../en/configuration.md) | [Оглавление документации](../index.md)

Приложение читает runtime-конфигурацию из `.env` в каталоге экземпляра.
`a-second-brain init` создаёт этот файл с правами `0600`. Никогда не добавляйте
его в Git и не копируйте значения в issue, логи или документацию.

## Обязательные параметры

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен Telegram Bot API от BotFather |
| `OWNER_TELEGRAM_ID` | Положительный числовой Telegram user ID владельца бота |

`DEEPGRAM_API_KEY` необязателен и включает распознавание голоса. Без него, а
также при сбое Deepgram бот всё равно сохраняет запись в `attachments/` и
запись в daily с пометкой «Не распознано»; ночной запуск распознает её, когда
ключ заработает (за сегодня и вчера).

По умолчанию `AI_CLI` равен `claude`, но выбранная команда должна быть
установлена и авторизована.

## Расписание

| Переменная | Назначение |
|---|---|
| `MORNING_BRIEF_TIME` | Время утреннего брифа, `HH:MM` (24 ч), по умолчанию `08:00` |
| `DAILY_PROCESS_TIME` | Время ночной обработки, `HH:MM` (24 ч), по умолчанию `21:00` |
| `SCHEDULED_PROCESS_HOUR` | Необязательный час `0`-`23`, начиная с которого плановый запуск считается не запоздалым; по умолчанию — час из `DAILY_PROCESS_TIME`. Неверное значение заменяется значением по умолчанию |
| `TIMEZONE` | Часовой пояс дня владельца (имя IANA, например `Europe/Moscow`); пусто — пояс системы |
| `CALENDAR_ICS_URL` | Приватная ICS-ссылка на календарь (только чтение); пусто — календарь выключен. См. [Интеграции](integrations.md#календарь) |

Установщики (`scripts/install-systemd-user.sh`,
`scripts/install-launchd-user.sh`) читают их из `.env` и останавливаются на
неверном значении. После смены времени запустите установщик заново. Выбирайте
вечернее время: запуск раньше `DAILY_PROCESS_TIME` считается запоздалым и
обрабатывает предыдущий день.

`TIMEZONE` определяет, к какому дню относятся запись, бриф и ночной проход
(запись, пришедшая в 22:30 UTC, попадёт в заметку следующего московского дня),
и что значит «напомни в 9». Время выше читается в этом поясе. Неизвестное имя
остановит бота при запуске, `doctor` его покажет. Пустое значение оставляет пояс
системы. Установщик systemd записывает пояс в два таймера; таймеры обслуживания
(QMD, проверка бэкапа, PLAUD) остаются на поясе системы. Оба установщика
(`install-systemd-user.sh`, `install-launchd-user.sh`) передают пояс всем
сервисам как `TZ=<TIMEZONE>`, поэтому скрипты навыков, журнал операций и
технические метки времени тоже считают время в поясе владельца. `TZ`, заданный
в `.env` явно, важнее выведенного из `TIMEZONE`. После смены `TIMEZONE`
запустите установщик заново.
Уже записанные заметки и напоминания при смене пояса не пересчитываются, а
`/undo` может не найти запись предыдущего дня вблизи момента смены.

## Основное поведение

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `AI_CLI` | `claude` | `claude`, `claude-tmux`, `codex`, `codex-tmux`, `qwen`, `gemini`, `kimi`, `grok` или `opencode` |
| `CONTENT_LANGUAGE` | `ru` | Язык сохраняемых и генерируемых материалов |
| `OWNER_FULL_NAME` | пусто | Имя владельца для назначения задач в промптах |
| `VAULT_PATH` | `./vault` | Приватный Obsidian-совместимый vault |

Значение `VAULT_PATH` должно совпадать с `memory_root` в
`vault-manifest.json`. В стандартной структуре используется `./vault`.

## Todoist

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `TODOIST_API_KEY` | пусто | Включает операции с задачами Todoist |

Для Todoist также нужны `mcp-cli`, `npx` и локальный `mcp-config.json`. Если
ключ не задан, `doctor` считает интеграцию отключённой.

## Извлечение веб-страниц

Если обычной HTTP-загрузки недостаточно, приложение пробует настроенные
сервисы извлечения содержимого.

| Переменная | Назначение |
|---|---|
| `TAVILY_API_KEY` | Tavily Extract |
| `JINA_API_KEY` | Jina Reader |
| `ZAI_API_KEY` | Резервный Z.AI Reader |
| `PROXY_URL` | Необязательный совместимый proxy reader |

Все параметры необязательны. Настраивайте только сервисы, чьи условия
приватности и хранения данных вам подходят.

## PLAUD

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `PLAUD_BEARER_TOKEN` | пусто | Включает импорт записей PLAUD |
| `PLAUD_REGION` | `api` | `api` или `api-euc1` |

Таймер PLAUD включается только при наличии токена во время установки systemd
units.

## Поиск и совместимый model gateway

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | API-ключ совместимого gateway |
| `OPENAI_BASE_URL` | Базовый URL OpenAI-совместимого API; старое имя `BASE_URL` тоже работает, при наличии обоих побеждает новое |
| `CLASSIFICATION_MODEL` | Модель Decisions API для обработки сообщений и решения о поиске в памяти; имеет приоритет над `OPENAI_MODEL` |
| `OPENAI_MODEL` | Модель чат-API для тех же решений, если `CLASSIFICATION_MODEL` пуста; если обе пусты — CLI. Старое имя `MODEL` тоже работает |
| `EMB_MODEL` | Удалённая модель эмбеддингов QMD; если пусто — локальная `Qwen3-Embedding-0.6B` |
| `RERANK_MODEL` | Модель reranking для QMD; если пусто — локальная `Qwen3-Reranker-0.6B` |

Пустые `EMB_MODEL` и `RERANK_MODEL` сохраняют полностью локальный режим и не
требуют `OPENAI_API_KEY` или `OPENAI_BASE_URL`. Локальные модели при первом
использовании загружаются с Hugging Face и по умолчанию работают на CPU.
Совместимость удалённого API с OpenAI не означает одинаковых условий
приватности.

## Зашифрованные резервные копии

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `VAULT_BACKUP_DIR` | `./.vault-backups` | Каталог зашифрованных снимков |
| `VAULT_BACKUP_GPG_RECIPIENT` | пусто | Получатель GPG; пустое значение отключает снимки |
| `VAULT_BACKUP_RETENTION` | `14` | Количество сохраняемых снимков |

Каталог резервных копий должен находиться за пределами `VAULT_PATH`. Закрытый
ключ расшифровки храните вне сервера приложения. Подробнее — в разделе
[Резервное копирование и восстановление](backup-and-restore.md).

## Переменные авторизации Gemini

Для Gemini могут использоваться `GOOGLE_API_KEY`, `GEMINI_API_KEY`,
`GOOGLE_APPLICATION_CREDENTIALS` или `GOOGLE_GENAI_USE_VERTEXAI`. Остальные
AI CLI используют собственные команды входа.

## Лёгкие модели для отдельных запросов CLI

`CliRunner.run(..., light=True)` сначала выбирает лёгкую модель для запроса
на чтение. Для Claude используется `haiku`, для Gemini — `flash-lite`.
Codex, Grok, Kimi и OpenCode предоставляют каталог через свои команды;
для Qwen читаются настроенные `modelProviders`. Выбираются известные лёгкие
семейства, внутри одного уровня — более новые числовые версии. Наличие
модели в каталоге не гарантирует доступ для текущей учётной записи.

При отказе выбранной модели выполняется один повтор без указания модели —
с обычными настройками CLI. Если каталог недоступен или лёгкой модели нет,
сразу используется модель по умолчанию. Ошибки сети, авторизации, квоты
и превышение времени ожидания не запускают другую модель. Обе попытки
укладываются в общий срок запроса. Выбор и переход записываются в журнал.
Варианты запуска через tmux также поддерживаются. Существующие вызовы
сохраняют обычную модель, пока явно не передан `light=True`.
Стрелочка в списке дел использует лёгкую модель для подготовки поиска через
CLI и итогового ответа. Другие вопросы и поручения сохраняют обычную модель.

## Проверка

После каждого изменения конфигурации запускайте:

```bash
a-second-brain doctor
```

Команда сообщает о наличии параметров, но никогда не выводит значения
секретов.
