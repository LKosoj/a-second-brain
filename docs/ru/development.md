# Разработка

[English](../en/development.md) | [Оглавление документации](../index.md)

Разработка ведётся в публичном дереве исходного кода и на обезличенных
fixtures. Никогда не используйте заполненный личный vault как тестовые данные.

## Окружение

```bash
uv sync --frozen --group dev
```

Минимальная поддерживаемая версия — Python 3.12. Runtime-зависимости
зафиксированы в `uv.lock`; при обычной установке группа разработки исключается.
Перед полным набором проверок отдельно установите на хост `shellcheck`.

## Проверки качества

Перед предложением изменения выполните:

```bash
uv run --frozen --group dev ruff check .
uv run --frozen --group dev mypy src
uv run --frozen --group dev pytest -q
shellcheck install.sh scripts/*.sh \
  src/d_brain/resources/vault_template/.claude/hooks/*.sh
bash -n install.sh scripts/*.sh
uv build
git diff --check
```

Тесты должны создавать временные vault либо читать упакованные шаблоны vault и
проекта. Они не должны зависеть от локального runtime-каталога `vault/`.

## Структура проекта

| Путь | Назначение |
|---|---|
| `src/d_brain/` | Устанавливаемый Python-пакет |
| `src/d_brain/resources/vault_template/` | Публичный обезличенный шаблон vault |
| `src/d_brain/resources/project_template/skills/` | Публичные скиллы проекта |
| `tests/` | Модульные и интеграционные тесты |
| `deploy/` | Шаблоны systemd user units |
| `scripts/` | Обёртки и инструменты настройки для исходного checkout |
| `docs/en`, `docs/ru` | Зеркальная документация оператора |

## Добавление или изменение команды CLI

1. реализуйте переиспользуемую логику в отдельном модуле;
2. подключите её через `d_brain.cli`;
3. оставляйте shell-скрипты тонкими обёртками, если нужна совместимость;
4. документируйте синтаксис, коды завершения и примеры на обоих языках;
5. проверяйте запуск из собранного wheel.

## Сборка и проверка дистрибутивов

```bash
uv build
unzip -l dist/a_second_brain-*.whl
tar -tzf dist/a_second_brain-*.tar.gz
```

Убедитесь, что в пакет включены ресурсы, `LICENSE` и `NOTICE`. Проверьте, что
в нём нет `.env`, заполненного корневого `vault/`, резервных копий, логов,
кэшей и локальных путей.

## Проверка в чистом окружении

Создайте временное окружение, установите собранный wheel, инициализируйте новый
экземпляр и выполните:

```bash
a-second-brain doctor /path/to/instance
```

Также проверьте, что `.env` имеет права `0600`, hooks сохранили признак
исполняемого файла, а новый Git-репозиторий игнорирует `.env` и `vault/`.

## Синхронизация документации

Каталоги English и Russian должны содержать одинаковые имена файлов. Каждая
страница ссылается на свою пару. Обновляйте обе версии вместе и запускайте
тесты документации.

## Проверка приватности

Перед публикацией:

- запустите secret scanner по всей подготовленной истории;
- найдите личные имена, названия организаций, пути хоста, токены и email;
- просмотрите имена отслеживаемых файлов;
- сохраните лицензионные атрибуции исходного проекта;
- используйте в тестах только вымышленных людей, организации и проекты.

Удаление секрета более поздним коммитом не отзывает его. Смените учётные
данные и перепишите ещё не опубликованную историю либо следуйте процедуре
инцидента площадки, если история уже опубликована.
