# Резервное копирование и восстановление

[English](../en/backup-and-restore.md) | [Оглавление документации](../index.md)

Перед изменением данных плановая write-heavy обработка может создать полный
зашифрованный снимок vault. Резервное копирование необязательно, но настоятельно
рекомендуется.

## Модель безопасности

- На сервере приложения хранится только открытый GPG-ключ получателя.
- Закрытый ключ расшифровки остаётся на другой доверенной системе.
- Каталог резервных копий расположен за пределами `VAULT_PATH`.
- Рядом с каждым зашифрованным архивом находится файл контрольной суммы
  SHA-256.
- Ротация сохраняет последние `VAULT_BACKUP_RETENTION` снимков.

Зашифрованный архив всё равно раскрывает метаданные: имя, время создания и
размер. Ограничьте доступ к каталогу резервных копий.

## Настройка резервного копирования

Импортируйте открытый ключ получателя в GPG keyring учётной записи сервиса.
Затем задайте:

```dotenv
VAULT_BACKUP_DIR=./.vault-backups
VAULT_BACKUP_GPG_RECIPIENT=backup@example.com
VAULT_BACKUP_RETENTION=14
```

Проверьте путь и команду:

```bash
a-second-brain doctor
uv run --frozen --no-dev python -m d_brain.run_vault_backup
```

Если `VAULT_BACKUP_GPG_RECIPIENT` пуст, команда сообщает, что резервное
копирование отключено, и успешно завершается. Если получатель указан, но
шифрование завершилось ошибкой, плановая обработка остановится до изменения
vault.

## Проверка снимка

На доверенной машине, где доступны зашифрованный файл и контрольная сумма:

```bash
sha256sum --check vault-YYYYMMDDTHHMMSSZ.tar.gz.gpg.sha256
```

Если проверка не прошла, не продолжайте восстановление.

## Безопасное восстановление

Никогда не распаковывайте архив поверх рабочего vault. Используйте новый
временный каталог:

```bash
restore_dir="$(mktemp -d /tmp/a-second-brain-restore.XXXXXX)"
gpg --decrypt vault-YYYYMMDDTHHMMSSZ.tar.gz.gpg \
  | tar -xzf - -C "$restore_dir"
```

Восстановленный vault окажется в `$restore_dir/vault`.

Перед заменой:

1. остановите units бота, обработки, PLAUD и QMD, которые могут писать данные;
2. сравните восстановленный vault с рабочим;
3. сохраните текущий рабочий vault отдельно для отката;
4. проверьте владельца и ограничительные права доступа;
5. переместите выбранный vault на рабочее место;
6. запустите `a-second-brain doctor`;
7. при необходимости пересоберите QMD и производное состояние графа;
8. запустите сервис и проверьте поведение в Telegram.

Проект намеренно не предоставляет автоматической разрушительной команды
восстановления.

## Проверка восстановления

Резервная копия не подтверждена, пока не выполнено пробное восстановление.
Периодически восстанавливайте снимок в изолированный каталог, проверяйте
несколько заметок и вложений и убеждайтесь, что закрытый ключ доступен
уполномоченному оператору.
