## Граница публичных и приватных данных

```text
публичный исходный код или wheel       приватный экземпляр
├── Python-приложение                  ├── .env
├── обезличенный шаблон vault    init →├── vault/
├── шаблоны systemd                    ├── .vault-backups/
└── тесты и документация               └── логи и runtime-state
```

Публичный репозиторий — канонический источник кода. Созданный vault —
канонический источник пользовательских знаний; он не должен попадать в
публичную историю Git.

## Основные компоненты

| Компонент | Ответственность |
|---|---|
| `d_brain.cli` | Точки входа `init`, `doctor` и `run` |
| `d_brain.doctor` | Диагностика установки и runtime |
| `d_brain.bot` | Авторизация Telegram, handlers, меню и доставка |
| `d_brain.control_plane` | Реестр workflow, routing, контекст и разрешённые записи |
| `d_brain.services` | Обработка, хранение, импорт, поиск, backup и интеграции |
| `d_brain.resources` | Обезличенные шаблоны проекта и vault |

`src/d_brain/control_plane/registry.py` — канонический каталог workflow.
Runtime-конструкторы промптов находятся в `src/d_brain/services/`. Упакованные
файлы фаз и политик помогают этим конструкторам, но не переопределяют реестр.

## Поток захвата

Telegram handlers авторизуют отправителя по `OWNER_TELEGRAM_ID`, определяют
тип входных данных и передают их специализированному сервису. Текст и голос
могут попадать в область ежедневного захвата; файлы, страницы, видео и записи
— в области импорта. При настроенной индексации доступные для поиска записи
обновляют производный индекс.

## Поток обработки

Интерактивная команда `/process` создаёт предварительный просмотр. Плановый
write-heavy workflow изолирует фазы capture, execute и reflect. Каждая фаза
получает только объявленный контекст и разрешённые действия. На границе
workflow Python проверяет и сохраняет результаты.

## Вопросы и поиск

Маршрутизация вопросов объединяет:

1. отобранный контекст vault;
2. скомпилированные briefings;
3. поиск QMD, если он доступен;
4. поиск по точному пути или строке для идентификаторов.

Производные сводки и индексы помогают поиску, но не являются источником
истины. Долговременные факты должны находиться в проверенном Markdown vault.

## Хранение и согласованность

`vault-manifest.json` задаёт корень памяти, разрешённые каталоги содержимого,
инфраструктурные области, бюджет контекста, индекс QMD и профили frontmatter.
Запись в vault использует защищённые пути и кооперативную блокировку. Для
рискованных миграций добавляются backup, остановка записи, доказательство
результата и предварительные проверки.

## Границы безопасности

- Секреты хранятся в `.env` с правами `0600`.
- Telegram отклоняет всех пользователей, кроме настроенного владельца.
- Hooks control plane запрещают runtime изменять управляемые prompt assets.
- Systemd user units работают без root с `NoNewPrivileges` и `PrivateTmp`.
- Резервные копии шифруются на открытый GPG-ключ получателя.
- Vault не публикуется как универсальный MCP-сервер.

Подробные контракты реализации и владения workflow описаны в
[справочнике control plane](../control-plane.md).
