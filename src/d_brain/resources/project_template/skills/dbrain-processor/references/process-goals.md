# Process Goals

Use this reference when a captured note or weekly goal should become a repeatable controllable commitment instead of a vague outcome task.

## Core Rule

Prefer goals the owner can execute directly:
- good: specific action, time block, or recurring cadence
- bad: vague desired outcome with no controllable next step

## Good Process Goal Properties

- owner-controlled
- time- or frequency-bounded
- trackable as done / not done
- small enough to survive a normal week

## Typical Conversions

| Outcome framing | Better process framing |
|---|---|
| "Закрыть сделку" | "Сделать follow-up клиенту завтра" |
| "Запустить продукт" | "2 часа deep work на MVP каждое утро" |
| "Найти клиентов" | "Отправлять 5 outreach-сообщений в день" |
| "Подготовить программу" | "30 минут research аналогов ежедневно" |

## Todoist Mapping

Use recurring due strings when the commitment is a real cadence:
- `every day`
- `every weekday`
- `every week`
- explicit weekday lists for fixed weekly rhythm

Use one-time due dates when the note describes a single checkpoint.

Decision rule:
- if the owner controls a repeatable cadence, use recurring;
- if the source describes one checkpoint, use one-time;
- if the wording is only an outcome wish, do not create a process goal yet.

## Anti-Patterns

- vague tasks like "поработать над проектом"
- oversized habits that are unlikely to survive execution
- outcome-only wording without an owner-controlled action
