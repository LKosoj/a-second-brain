# Wiki-Links Building

Build the graph from meaning, not from shared vocabulary.

## Search Strategy

When saving a new thought or update:
- check the source note first so links explain the actual context, not only the topic,
- inspect relevant MOCs,
- inspect `business/_index.md` / `projects/_index.md` when entities are involved,
- then add only links you can justify.

## Good Link Reasons

Use typed relationships such as:
- `extends`
- `context`
- `supports`
- `contradicts`
- `enables`
- `requires`

Each link should answer: “why are these connected?”

## Goal Links

Link to goal files only when the note materially advances a current weekly, monthly, or yearly direction.

## MOC Updates

Add new notes to the appropriate MOC when it improves navigation.
Do not duplicate the same note across many MOCs without a strong reason.
Prefer one hub update plus a few strong direct links over broad backlink spraying.

## Business / Project Linking

When a note touches a real client, relationship, deal, or initiative:
- resolve it through the existing vault structure first,
- prefer the most specific existing note,
- avoid fabricating a path because the name looks plausible.

## Anti-Patterns

Avoid:
- keyword-only links,
- decorative backlinks,
- naked `## Related` dumps without a context phrase,
- stale year-specific goal references,
- and broad “related to everything” sections.
